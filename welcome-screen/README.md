# 数智科技产业学院 · 2026 迎新报到大屏

本地运行的迎新报到系统。数据来自工作区的《26级新生信息汇总.xlsx》，大屏样式参考所提供效果图，使用学院原始标志。

## 启动与访问

当前电脑已配置 Node.js 与 MySQL，数据库名为 `welcome2026`。数据库密码与后台登录密码只保存在本地 `.env`。

```powershell
cd F:\新生迎新可视化大屏\welcome-screen
npm install
npm run setup
npm run build
npm start
```

- 大屏：<http://localhost:3000/>
- 教师工作台：<http://localhost:3000/admin>
- 管理员账号：`admin`，密码见 `.env` 的 `ADMIN_PASSWORD`
- 专业教师账号：`npm run setup` 首次运行时自动生成并打印（如 `ai` / `bigdata` / `fintech` / `ecom`），同时记录在 `data/teacher-accounts.txt`（已被 Git 忽略）。再次运行 setup 不会改动已有账号密码。

也可以双击工作区的 `启动迎新大屏.cmd`。启动窗口保持运行即可；关闭窗口会停止应用。

同一局域网内，用服务器电脑的 IPv4 地址替换 `localhost`，例如当前电脑的 <http://192.168.1.13:3000/> 与 <http://192.168.1.13:3000/admin>。IP 变化后请以 `ipconfig` 的实际地址为准。若其他电脑无法访问，在 Windows 防火墙中为 Node.js 或 TCP 3000 允许专用网络访问。MySQL 与 API 不需要开放给客户端。

开发修改时运行 `npm run dev`，同时启动页面与后台，页面自动刷新。不要同时运行开发和生产启动脚本，它们使用同一组端口。

## 老师现场操作

1. 登录教师工作台，按姓名、名册编号或学校搜索，并核对学生的完整班级。同名学生保留不同名册编号。专业教师账号只能查看和操作本专业学生；管理员可管理全院。
2. 点击“确认报到”，核对弹窗后确认。也可选中当前页学生后批量确认。除报到外，可将学生标记为“请假”（仍计入应到）或“退学”（自动从应报到总人数与大屏统计中移除）；行内下拉可随时改回“待报到”，原报到序号保留。
3. 全院报到率、专业/班级报到率、地区已报到人数、每小时统计及最近 5 人通过 SSE 自动更新。
4. 已报到学生可打开“合影卡”，点击“推送至大屏”展示姓名、班级、地区和全院报到序号，持续 2 分钟；也可提前点击“结束大屏合影展示”。大屏本地可点击最近报到学生打开合影卡。
5. 登记错误时点击撤销图标并确认。报到总人数回退，但该生首次获得的序号保留，重新报到沿用，防止已拍合影的序号重复。
6. 地图资料缺失时点击铅笔图标，补充生源城市、区县和学校。保存即更新地图。
7. “操作记录”可查看最近 100 次报到、撤销及资料修改；完整记录保留在数据库中。

## 大屏展示

- 布局按提供的《大屏布局.jpg》重排，采用石墨黑、银白和冰蓝的统一色系。地图上方依次展示应报到、已实到、今日入校速度、全院报到率；入校速度按最近 60 分钟内的有效报到人数计算。
- 左侧专业与班级明细同时展示；班级明细每 8 秒轮播，覆盖全部 11 个班级。下方专业性别环形图每 10 秒轮播，可暂停或手动切换。
- 中央山东 16 地市热力图，颜色表示生源人数。鼠标悬停、点击或键盘聚焦可查看同乡总人数、已报到人数及该地全部生源学校；学校区域可滚动。
- 右侧依次为名字末字动态词云、星座环形图、兴趣特长。星座每 12 秒轮播全院及四个专业；兴趣可切换词云和前六项兴趣人数雷达图。词云悬停显示对应人数。
- 地图下方并排展示 24 小时报到折线趋势与最近 5 位报到学生。点击学生可打开专属合影卡。
- 支持全屏及窄屏布局，遵循系统减少动态效果设置。建议现场使用 1920×1080 或更高分辨率屏幕。
- 断线后显示连接提示并自动重连，不将缓存数字标为实时。

## 数据口径与缺失

| 项目           | 核对结果                   |
| -------------- | -------------------------- |
| 在册新生       | 450 人                     |
| 专业 / 班级    | 4 个 / 11 个               |
| 招生资料       | 176 条，全部匹配到在册学生 |
| 已知生源地区   | 176 人                     |
| 地区待补充     | 274 人，不虚构地域分布     |
| 有效公历生日   | 450 人                     |
| 已识别兴趣标签 | 303 人                     |

报到分母使用四个专业的班级明细，招生资料不重复计入总人数。资料按专业与姓名匹配；同专业重名时核对出生日期。地区按照考生号中的地级市代码确定，原地区字段保留为区县。生日以班级名册为准。招生资料补齐了原班级名册中缺失的性别。

名字末字统计覆盖 450 人，画面展示前 28 个高频字。兴趣按明确关键词分类，每名学生在每个标签中只计一次；无法识别的自由文本不强行分类，画面展示前 21 个标签。星座、词云与生源热力图描述全部在册新生；报到进度、最近到校及各城市已报到人数随报到变化。

所有新导入学生的初始状态为“待报到”，没有虚构报到人数。第一次报到以老师确认时间为准。序号可能因撤销出现空缺，不能用最大序号代替当前已报到人数。所有报到统计按中国标准时间计算。

## 数据存储和维护

- `.env`：本地 MySQL 与教师账号配置。修改教师密码后重启应用；数据库账号仅用于后端连接。
- `data/students.json`：从工作簿提取的私有导入数据，未放入公开目录，已加入 Git 忽略。
- `data/import-report.json`：匹配、缺失与统计口径报告。
- `server/setup.mjs`：建表与幂等导入。再次运行不会重置已报到状态、已有序号或老师已修改的资料；若同一名册编号对应的姓名/班级变化，会中止导入，要求人工核对。
- `server/service.mjs`：事务内分配序号及统计逻辑。
- `audit_log`：操作历史。`students`：当前状态及永久序号。`settings`：导入报告和合影推送状态。

如源工作簿内容调整，可使用 Python（需要 `openpyxl`）运行 `scripts/prepare-data.py` 重新生成提取结果。对已存在学生的修改请在后台完善生源资料；名册增删、调班和身份冲突需要核对后迁移，不能直接覆盖正式报到记录。

正式报到前建议备份数据库。可运行 `mysqldump -u root -p --default-character-set=utf8mb4 welcome2026 > welcome2026-backup.sql`，按提示输入数据库密码。不要将包含学生数据的备份放到 `public` 目录。

后台使用独立教师密码、HttpOnly 登录会话、同源 JSON 请求校验和参数化 SQL；学生生日、完整兴趣原文与导入原始记录不会通过大屏接口公开。当前面向可信校园局域网运行；未配置公网 HTTPS 或学校统一身份认证。

## 验证

`npm test` 创建随机命名的独立 MySQL 测试库，验证导入统计、登录保护、并发序号、重复提交、整批回滚、撤销重报、SSE、合影资格、资料修改与重复导入保留数据，结束后仅清理该测试库。不会改动正式库。

`npm run build` 执行 TypeScript 检查及生产构建。运行 `npm start` 后可使用 `/api/health` 检查数据库连接。

可选 WebMCP：教师页在浏览器支持时注册 `search_new_students`，用于查询新生并同步页面筛选。未在支持 WebMCP 的浏览器环境中实测，该能力不影响常规操作。

## 地图来源

地图边界来自 [阿里云 DataV GeoAtlas](https://help.aliyun.com/zh/datav/datav-7-0/user-guide/datav-geoatlas-widgets/)，[山东省 GeoJSON](https://geo.datav.aliyun.com/areas_v3/bound/370000_full.json) 已缓存于 `public/shandong.json`，运行时无需外部地图服务。DataV 文档标明其地图数据来自高德开放平台，仅供学习交流；实际公开展示前应按学校地图使用要求核对授权。项目未上传新生数据到任何外部服务。
